## 五、编辑器输入卡顿 + 模糊跟随 + 进度条修复（2026-08-04 已落地，用户验证 OK）

### 5.1 编辑器输入卡顿
- 现象：主页全屏透明(overlay)→编辑器，输入/删除/选区高亮延迟；全屏壁纸(fullscreen)→编辑器无此问题。
- 根因：`#editor-bg-layer` 持久 `will-change:transform` + `transform:scale(1.05)` 把全屏层钉成独立合成层，每次输入触发整页合成时模糊层被迫重算 → 主线程阻塞。
- 修复：
  1. `layout-styles.css` `#editor-bg-layer` 删除 `will-change:transform`。
  2. `Layout.astro` `freezeWallpaperForEditor.apply()` 把 1.05x 从 `transform:scale(1.05)` 改为 `background-size` 烘焙（`sw*1.05 × sh*1.05`，`bgX/bgY` 用放大后值重算）。
  3. `filter` 统一 `blur(var(--overlay-blur,0px))` 跟随全局主题变量（不再用 `editorSrcMode` 二选一，删除该变量）。
- 用户约束（改此体系严禁违反）：导航栏对齐、滚动条、背景图位置/宽度/右边自然露图——四项绝不动；模糊跟随主题，编辑器不另设专属模糊。

### 5.2 全屏壁纸进编辑器背景透明 + 调模糊 px 无效
- 原以为 bug，实为 `editorSrcMode==='fullscreen' → filter:none` 写死。用户要求"模糊跟随主题"，确认走方案 A：编辑器 blur 统一读全局 `--overlay-blur`，壁纸来源进编辑器也会模糊且可调。用户验证：模糊跟随正常、不卡。

### 5.3 透明设置面板进度条显示一半
- 现象：主页全屏壁纸→编辑器，打开设置面板，进度条填充约一半（数值正确、可拖动）。
- 根因：进度条 `--range-progress` 样式变量只在组件 `onMount` 初始化一次；设置面板是 Swup 外部组件不重挂载，切编辑器后透明面板新插入 DOM 未重算样式 → 停在 50% fallback。
- 修复：`DisplaySettingsIntegrated.svelte` 的 `wallpaperModeChange` 监听切到 `overlay` 时 `requestAnimationFrame(refreshAllRangeProgress)`。用户验证 OK。
- 三处改动均 0 lint 错误；改动文件：`src/styles/layout-styles.css`、`src/layouts/Layout.astro`、`src/components/controls/DisplaySettingsIntegrated.svelte`。

## 七、白条根因彻底查清 + banner 专属修复（2026-08-04 第二次尝试，待用户验证）

### 为什么只有 banner 出问题（核心结论，务必记住）
编辑器注入的 `body.editor-page #wallpaper-wrapper { position:fixed; inset:0; height:100vh; ... }` 在过渡期一直生效（page:view 才清理），三种目标模式表现不同：

| 目标模式 | 原生定位（layout-styles.css） | 被编辑器规则压制后 | 结果 |
|---|---|---|---|
| overlay | `fixed; inset:0; 100%; 100vh; top:0`（L673-688） | **与编辑器规则完全等价** | 无冲突，正常 |
| fullscreen | `relative; 100vh; min/max-height:100vh; top:0`（L726-734） | 变 fixed，但仍整屏 100vh 顶部对齐，铺满盖得住 | 视觉无差异，正常 |
| **banner** | `.enable-banner #wallpaper-wrapper { height: var(--banner-height-home); transform: translateY(var(--banner-height-extend)) }`（Layout.astro:596-599，**无 !important**） | 被 `height:100vh !important`+fixed 完全压制，transform 失效 | 壁纸钉死、内容按 banner 下滑，错开处露 body 背景 = **白条** |

一句话：overlay/fullscreen 目标态都是「整屏+顶部对齐」，与被钉成 fixed 全屏视觉等价；只有 banner 是「部分高度+位移」，本质冲突。

### 本次修复（4 处，全部 banner 专属，未动任何公共规则）
1. 新增 CSS（紧跟原规则后，原规则一字未改）：
   `body.editor-page.editor-leaving-banner #wallpaper-wrapper { position:relative !important; inset:auto !important; left/top:auto !important; width:100% !important; height:var(--banner-height-home) !important; transform:translateY(var(--banner-height-extend)) !important; }`
   —— 不用 `position:static`，而是**精确复现 .enable-banner 原生几何**，让壁纸回到文档流与内容同步下滑。
2. `visit:start` 离开分支：仅 `if (savedMode === 'banner')` 才 `add('editor-leaving-banner')`。
3. `removeEditorModeLayout()` 清 class。
4. `applyEditorModeLayout()` 兜底清 class（防导航中断残留）。

- **绝不调 `unfreezeWallpaper()`**（上次的元凶：过渡期拆冻结层导致 fullscreen/overlay 背景跳变）
