# 企业级全栈应用开发终极手册（一级标题）

## 第一章：项目启动与需求分析（二级标题）

### 1.1 干系人识别与用户画像（三级标题）

#### 1.1.1 内部角色定义（四级标题）
- 产品经理：需求拆解与优先级排序
- 前端工程师：界面交互与状态管理
- 后端工程师：API 设计与数据建模
- 运维工程师：CI/CD 与基础设施

#### 1.1.2 外部用户分层（四级标题）

##### 1.1.2.1 访客用户（五级标题）
仅能浏览公开文档，无写入权限。

##### 1.1.2.2 注册用户（五级标题）
可发表评论、创建项目。

###### 1.1.2.2.1 付费会员特权（六级标题）
解锁高级分析图表、专属客服通道。

###### 1.1.2.2.2 企业版管理员（六级标题）
可管理组织成员、审计操作日志。

### 1.2 技术选型与评估（三级标题）

#### 1.2.1 前端技术栈对比（四级标题）
- React 18 + Next.js 14
- Vue 3 + Nuxt 3
- SvelteKit

#### 1.2.2 后端框架选型（四级标题）

##### 1.2.2.1 Node.js 生态（五级标题）
使用 NestJS 作为企业级 MVC 框架。

##### 1.2.2.2 Go 语言生态（五级标题）
使用 Gin + GORM 组合。

### 1.3 里程碑与时间规划（三级标题）

#### 1.3.1 第一阶段：MVP 开发（四级标题）
周期 4 周，交付核心登录与数据看板。

#### 1.3.2 第二阶段：功能迭代（四级标题）
周期 6 周，集成支付网关与通知中心。

## 第二章：开发环境标准化（二级标题）

### 2.1 容器化配置（三级标题）

#### 2.1.1 Dockerfile 编写规范（四级标题）
使用多阶段构建减少镜像体积。

#### 2.1.2 Docker Compose 编排（四级标题）
定义 `services`：前端、后端、Redis、PostgreSQL。

##### 2.1.2.1 环境变量注入（五级标题）
区分 `.env.dev`、`.env.staging`、`.env.prod`。

###### 2.1.2.1.1 敏感信息加密方案（六级标题）
使用 Vault 或 AWS Secrets Manager。

### 2.2 代码格式化与 Lint（三级标题）

#### 2.2.1 ESLint + Prettier 配置（四级标题）
继承 `@antfu/eslint-config`。

#### 2.2.2 Husky + lint-staged（四级标题）
在 pre-commit 阶段自动修复格式。

## 第三章：核心业务逻辑实现（二级标题）

### 3.1 认证与授权模块（三级标题）

#### 3.1.1 JWT 双令牌机制（四级标题）

##### 3.1.1.1 Access Token（五级标题）
有效期 15 分钟，携带用户角色信息。

##### 3.1.1.2 Refresh Token（五级标题）
有效期 7 天，存储在 Redis 中。

###### 3.1.1.2.1 令牌刷新流程（六级标题）
前端拦截器检测 401 自动调用 `/refresh` 接口。

###### 3.1.1.2.2 强制下线策略（六级标题）
修改密码后立即失效所有旧令牌。

#### 3.1.2 RBAC 权限模型（四级标题）

##### 3.1.2.1 权限粒度控制（五级标题）
页面级 + 按钮级 + 数据级权限。

### 3.2 支付与结算逻辑（三级标题）

#### 3.2.1 接入三方支付（四级标题）
支持微信支付、支付宝、Stripe。

#### 3.2.2 回调幂等性处理（四级标题）

##### 3.2.2.1 唯一订单号去重（五级标题）
使用数据库唯一索引防止重复入账。

##### 3.2.2.2 分布式锁保障（五级标题）
基于 Redisson 实现。

### 3.3 消息通知系统（三级标题）

#### 3.3.1 实时 WebSocket 推送（四级标题）
使用 Socket.IO 建立长连接。

#### 3.3.2 延迟消息队列（四级标题）
使用 BullMQ 处理定时邮件/短信提醒。

##### 3.3.2.1 重试与死信机制（五级标题）
失败 3 次后进入死信队列人工介入。

## 第四章：数据库设计与缓存策略（二级标题）

### 4.1 关系型数据库设计（三级标题）

#### 4.1.1 用户表与角色表（四级标题）
一对多关联，使用外键约束。

#### 4.1.2 订单表分区策略（四级标题）

##### 4.1.2.1 按月份范围分区（五级标题）
提升历史数据查询效率。

##### 4.1.2.2 索引优化建议（五级标题）
联合索引 `(user_id, created_at)`。

### 4.2 NoSQL 与缓存设计（三级标题）

#### 4.2.1 Redis 数据结构使用（四级标题）
- String：分布式锁、验证码
- Hash：用户会话信息
- Zset：排行榜数据

#### 4.2.2 缓存穿透与雪崩解决方案（四级标题）

##### 4.2.2.1 布隆过滤器（五级标题）
拦截不存在的 Key。

##### 4.2.2.2 随机过期时间（五级标题）
避免大量缓存同时失效。

## 第五章：前端架构与交互设计（二级标题）

## 第七章：性能调优与监控（二级标题）

### 7.1 前端加载性能（三级标题）

#### 7.1.1 代码分割与懒加载（四级标题）
使用 `React.lazy` 和 `next/dynamic`。

#### 7.1.2 静态资源 CDN 加速（四级标题）

### 7.2 后端响应性能（三级标题）

#### 7.2.1 数据库查询优化（四级标题）
使用 EXPLAIN 分析慢 SQL。

#### 7.2.2 异步非阻塞 IO（四级标题）
Node.js 使用 Worker Threads 处理 CPU 密集型任务。

##### 7.2.2.1 连接池调优（五级标题）
最大连接数设置为 CPU 核心数的 2 倍。

## 第八章：安全防护策略（二级标题）

### 8.1 网络安全（三级标题）

#### 8.1.1 HTTPS 强制与 HSTS（四级标题）
配置 Strict-Transport-Security 头。

#### 8.1.2 CORS 与 CSP 策略（四级标题）
限制可信域名白名单。

### 8.2 应用层安全（三级标题）

#### 8.2.1 XSS 与 CSRF 防御（四级标题）
- 输出转义（XSS）
- SameSite Cookie + Token（CSRF）

#### 8.2.2 注入攻击防御（四级标题）

##### 8.2.2.1 SQL 注入（五级标题）
使用参数化查询或 ORM。

##### 8.2.2.2 NoSQL 注入（五级标题）
过滤用户输入的特殊操作符（如 `$where`）。

#### 12.2.1 数据库迁移准备（四级标题）
